# 数据审计：问题 → 经典处理方法 → 本项目的处理（2026-10-28）

范围：官方 train 2791 / val 365 / test 358 患者，10 张结构化表、基因组 888 个文件、DICOM 200 个文件。脚本 `analysis/data_audit_a.py`、`data_audit_b.py`；干净数据集 `analysis/build_clean_dataset.py` → `analysis/clean/`。所有数字来自本机实际计算。

## 1. 队列与划分（A1、A2）

| split | n | 年龄中位 | 女性 | anchor 年中位 | 落在"生者带"(anchor>2015.4) | 窗口内死亡 | 事件数中位 | 历史年数中位 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| train | 2791 | 64.3 | 0.440 | 2015.7 | 0.545 | 0.430 | 189 | 43.1 |
| val | 365 | 65.1 | 0.452 | 2015.6 | 0.551 | 0.425 | 189 | 44.2 |
| test | 358 | 63.4 | 0.450 | 2015.7 | 0.528 | （隐藏） | 194 | 43.0 |

**对抗验证**（用全部历史特征区分两个划分，5 折 AUROC）：train vs test 0.477，train vs val 0.494，val vs test 0.488，train 随机对半 0.483。三个划分在协变量上不可区分；val 的"偏易"（§4）是标签抽样的运气，不是分布偏移。因此**测试分数的合理预期是 OOF 分数**（≈0.21），不是 val 分数（≈0.26）。

经典方法：adversarial validation、分层抽样核对、协变量平衡表。

- 词表很小（每表 ≤160 个编码），稀疏阈值 20 人即可；"长尾编码"不是问题。
- 测试表：所有 START/DATE < anchor；**STOP > anchor 全部置空**（用药表 1,049 个空 STOP）；imaging_studies 测试行 0 条晚于 anchor。训练侧必须复制这一截断，否则"仍在用药"特征分布不一致（已处理）。
- REASONCODE：用药/操作 100% 引用已确诊条件；照护计划 3.1%、就诊 1.9% 引用首诊日期晚于本行的条件（Synthea 同日先后顺序问题），anchor 前用药引用"未来窗口内首诊的目标"仅 7 行。与 conditions 冗余，不使用。
- 字段排除：DEATHDATE、费用/支付、身份字段、STOP 日期本身。

经典方法：泄漏审计（Kaufman et al. 2012, *Leakage in Data Mining*）、按时间截断的特征构造（landmarking）、训练侧复刻测试侧预处理。

## 3. 时间结构（A4）

- wellness 就诊间隔 10%–90% 分位全部是 1.02 年：Synthea 的固定节律，时间间隔本身没有信息。
- anchor 前事件按年代：1990s 16.5 万、2000s 15.3 万、2010s 43.5 万。2010 年后事件密度是此前的 3 倍（Synthea 新模块、QoL 观测、实验室检查扩展），这就是年代可被回归出来的原因。
- 记录起点：首个事件年龄中位 18.1 岁（25% 在 25 岁后），与出生年相关 0.89；1,795 人存在 >10 年的就诊空白（起点中位 27 岁）。因此"距今多久"类特征要允许大值，"序列位置"没有稳定含义。

经典方法：时间抽象（temporal abstraction：计数/最近/首次/窗口统计），而不是依赖等间隔序列。

## 4. 日历年代与死亡耦合（A5、B4）

| 通道 | 对窗口内死亡的 AUROC | 性质 |
| --- | ---: | --- |
| anchor 日历年 | 0.989 | 任务设计 artifact |
| 是否有 anchor 前 QALY/DALY/QOLS 观测 | 0.937 | 年代标记（2011 年起） |
| 仅 token 是否出现（去 QoL） | 0.874 | 分散在词表中的年代信息 |
| 全部历史特征（计数/最近/数值） | 0.997 | 上述总和 |

纯年代 token（≥100 人且 2005 年后才出现）只有 5 个：QALY、DALY、QOLS、MCV4 脑膜炎球菌疫苗（2005）、带状疱疹疫苗（2006）。去掉它们仍能从编码组合回归 anchor 年（R² 0.57，MAE 7.4 年）。

**处理决定**：年代信息无法剔除，也是题目构造的一部分（测试集同样构造，anchor 年分布一致）。主线保留结构化表的全部观测，不加 anchor 日历日期这一显式特征；提供"去 QoL"敏感性版本；在报告里明确说明"终末目标 ≈ 死亡预测"这一事实。

经典方法：period/cohort effects 的识别、敏感性分析、informative censoring 的披露。

## 5. 附属文件（B1、B2）

**基因组（888 人：train 713 / val 87 / test 88）。** 每个文件固定 322 行、161 个 rsID、104 个基因，几乎全是心血管基因（LPA、PCSK9、LDLR、APOE、F5、MYBPC3…）。谁有 DNA 文件：

| 一生中患有 | 有 DNA 者 | 无 DNA 者 | 比值 |
| --- | ---: | ---: | ---: |
| 中风 | 0.780 | 0.026 | 30× |
| 心脏骤停 | 0.181 | 0.013 | 14× |
| 心梗 | 0.156 | 0.029 | 5.4× |
| 步态异常 / 脑微出血 | 0.268 | 0.055 | 4.8× |

中风患者携带的变异等位基因中位数 28，非中风者 0；rs10033464(LPA)、rs964184(ZPR1) 等 20 多个位点的携带者**一生中中风率 100%**。这不是遗传风险，而是 Coherent 数据集"让 DNA 与病历相符"的生成方式——变异是**根据完整病历（含 anchor 之后）**分配的。对 anchor 前无中风者，"有 DNA 文件"预测窗口内中风 AUROC 0.857；DNA 患者的中风 30% 落在窗口内。**判定：标签派生信号。** 第 1–6 轮主提交不使用；第七轮（2026-10-29）按 README 的明确许可（“You may use any modality provided (structured CSV, imaging, genomics)”，“optional enrichment”）和用户决定改为使用，报告中如实披露其生成方式与效应（见下文补记与 diagnosis 文档 §10.4）。

**能不能“去泄漏”后使用（2026-10-29 补）？** 不能，因为去掉泄漏后什么都不剩。把 train 中至风险（anchor 前无中风）的 2,388 人按是否有 DNA 文件分开：有文件者 317 人窗口内中风率 49.8%，无文件者 2.3%（单比特 AUROC 0.847、AP 0.402）。再按 anchor 前是否已有心梗 / 冠心病 / 心衰（可以“解释”其进入心血管队列的历史）分层：**已解释**的 83 人窗口内中风率仍是 32.5%（同层无文件者 2.4%），**未解释**的 234 人 56.0%（同层 2.3%）。即对 anchor 前历史做条件化并不能中和它。文件内容更直接：至风险的 DNA 患者中，窗口内将中风者携带变异等位基因中位数 37 个，不中风者 0 个，仅凭变异数在持有者内部区分窗口中风的 AUROC 0.969。信息分解是 I(DNA) = f(anchor 前诊断) + g(anchor 后诊断)：前者结构化表里已有，后者就是标签。任何“处理”若要去掉 g，就只能把文件整个丢掉；作为训练期辅助标签也无增益，因为训练患者 anchor 后的诊断本就可以直接从 conditions 表取，且同类的“兄弟目标辅助”实验为负。

**patients.csv 的 HEALTHCARE_EXPENSES / HEALTHCARE_COVERAGE（2026-10-29 第八轮发现，未使用，待决定）。** 这两列是 Synthea 对患者**整个记录期**（含 anchor 之后 5 年）累计的医疗费用与保险覆盖额。出题人在 test 的 patients.csv 里把 DEATHDATE 清空了（358 人全空），但这两列原样保留（358 人全有值，分位数与 train 同量级：中位 127 万 vs 135 万）。它们直接聚合了 anchor 后就诊的费用，因此是最字面意义的“跨 anchor 泄漏”：在 train 至风险患者上，COVERAGE 对窗口内肺癌三联的单变量 AUROC 0.81，EXPENSES 0.70；在第七轮最终分上叠一个 [分数, EXPENSES, COVERAGE, 年龄, 费用/年龄] 的逐目标 LightGBM（5 折），肺癌三联 AP 0.30 → 0.86，9 个目标增益 > 0.01，整体 OOF 0.2671 → 0.3112。对窗口内死亡本身没有信息（AUROC 0.42 / 0.54），信息全在“窗口里做了什么治疗”。与 genomics 的区别：README 明确许可 genomics / imaging，而这两列不是被许可的模态，是出题人清理 test 时的遗漏，且 README 写明 “Avoiding leakage across the anchor is part of what we assess”。**用户于 2026-10-30 决定使用。** 第八轮起作为特征进入全部模型家族：原始两列 + anchor 前 1 / 5 年支出窗口 + 两阶段残差（用 anchor 前历史和 P(死亡) 预测 log 终生费用后的残差）+ 残差 × P(死亡) 交互（`analysis/build_cost_features.py`、`build_cost_features_v2.py` → `clean/cost_features{,_v2}.parquet`）。会计恒等式检验表明这两列不是事件表费用之和（表内费用只占 0.5%–17%），机理、分层效应与模型设计见 diagnosis 文档 §10.5；报告中如实披露。

**DICOM（200 人：train 196 / val 2 / test 2）。** 全部为头颅 MR；拥有者步态异常/脑微出血 100%、Alzheimer 46%。同样是按诊断队列生成；测试只有 2 人，无论合法性都无实际影响。**第七轮起只用 StudyDate 在 anchor 当天或之前的 169 份作为一个指示位 `has_dicom_pre`**（按“只用 anchor 前事件”的规则过滤；像素数据不用）。 `imaging_studies.csv` 作为结构化事件表（anchor 前 1,275 行）可以使用，已纳入。

经典方法：数据来源溯源（provenance）、"too good to be true"检验、单变量泄漏筛查。

## 6. 数值观测（A6）

- 32 个数值 LOINC 码 ≥150 人；范围合理（收缩压 p01–p99 101–175，BMI 16.9–36.8）。
- 5 个码有两种单位且量纲不同：eGFR `33914-3` mL/min（中位 73.9）与 mL/min/1.73m²（中位 25.3，CKD 模块）、白蛋白 g/L vs g/dL、ALT/AST/ALP U/L vs [iU]/L（各 5 行）。按 code+unit 分键。
- QALY/DALY/QOLS 是 Synthea 的生命质量簿记值（年更新），不是化验；保留但标注。
- 37 个分类观测码；吸烟状态 `72166-2` 覆盖 3,040 人（肺癌模块的输入），作为 token 使用。
- 原项目的 8 档等频分箱对阈值型模块（肥胖 = BMI≥30、前驱糖尿病 = HbA1c 阈值）不友好；树模型直接吃原始值。

经典方法：单位归一、异常值截断、保留原值给树模型 / 阈值感知分箱给线性模型。

## 7. 标签结构（见 diagnosis 文档 §1，摘要）

- 40 类分三组：15 类无记忆意外（天花板 AP≈0.10）、10 类死亡对齐终末、15 类模块链条。
- 终末事件的时间：心梗窗口内首诊中位第 4.98 年（= 死亡当天）、肺炎 4.97 年、肺癌 1–3 年（固定生存期）。
- 重复标签：肺癌三联 Jaccard 0.89–0.99、步态/微出血 1.00、前列腺肿瘤/原位癌 0.79。
- 链条风险对"距前驱多久"不敏感（骨质疏松→病理性骨折各时段 0.21–0.45，CHD→心梗 0.2–0.4）：按状态的常数风险，编码"是否出现过"即可，顺序和间隔信息很少。
- 至风险人群：肥胖 50%、前驱糖尿病 41%、病毒性鼻窦炎 41% 的训练患者 anchor 前已确诊，不在风险集。

## 8. 干净数据集的定义（`analysis/build_clean_dataset.py`）

输入：10 张结构化表（含 imaging_studies），事件日历日期 < anchor；去重；词表与数值码阈值在 train 上拟合（≥20 / ≥50 人）。
特征块：每个 token 的 全史计数 / 近 5 年 / 近 1 年 / 最近距今 / 首次距今；数值码（code+unit）的 末值 / 极值 / 近 5 年均值 / 标准差 / 次数 / 趋势；anchor 时仍在用药（STOP 为空，train 复刻测试截断）；年龄、性别、种族、历史长度、各类事件数、就诊类别频率；既往目标状态。
排除：基因组、DICOM、REASONCODE、STOP 日期、DEATHDATE、费用/身份字段、anchor 日历日期。
可选：`--no-qol` 去掉 QALY/DALY/QOLS。
输出：`analysis/clean/X.parquet`（行序 = 患者表顺序）与 `manifest.json`（规则、各块维度、计数）。

## 9. 干净数据上的基线（`analysis/pipeline_clean.py`，train 5 折 × 2 OOF）

GBM 两配置 × 5 折 × 2 重复，折模型平均；特征 2,317 维（manifest 见 `analysis/clean/manifest.json`）。

| 数据版本 | OOF mAP | 意外 / 终末 / 链条 | val mAP | val macro-AUROC |
| --- | ---: | --- | ---: | ---: |
| 干净结构化表（主线） | **0.2092** | 0.096 / 0.415 / 0.185 | 0.2551 | 0.7739 |
| 去 QALY/DALY/QOLS（敏感性） | 0.2007 | 0.096 / 0.386 / 0.182 | 0.2464 | 0.7629 |
| + "有 DNA 文件"一位（第六轮前仅记录） | 0.2315 | 0.096 / 0.419 / 0.242 | 0.2761 | 0.7827 |

仅加入"是否有 DNA 文件"这一个比特，中风的 OOF AP 从 0.199 升到 0.674，总 mAP +0.022——比本项目所有建模改动加起来都大。这正是它必须被排除的原因：一个与临床无关的文件存在性不可能有这种效应，除非它是由标签生成的。

- 干净版与审计前的特征集（0.2104）持平：被排除的来源（基因组、DICOM、REASONCODE）此前就没有进模型，新增的 imaging_studies / 仍在用药 / 单位分键没有可测收益。
- QoL 三个观测值值 0.0085 OOF，全部落在终末组（0.415 → 0.386）：它们是年代/死亡代理，不是临床信号。主线保留它们（结构化表的一部分，测试集同构），报告中给出这一敏感性。
- 干净数据 + 混合 Transformer（全史 wide 通路）5 折 OOF = 0.1733，仍低于 GBM；见 diagnosis 文档 §7.3。

**对测试分数的预期**：对抗验证表明 test 与 train 同分布，因此预期 ≈ OOF 0.21（val 0.255 是偏易样本）。`predictions_clean.csv` 为干净主线的测试预测（重复目标组平均、已确诊置 0）。
